# 2. 编译
`gcc/g++ 选项 源代码文件1 源代码文件2 源代码文件n`

常用选项：
- `-o` 指定输出的文件名，这个名称不能和源文件同名。如果不给出这个选项，则生成可执行文件 `a.out` 。
- `-g` 如果想对源文件进行**调试**，必须加入这个选项。
- `-On` 在编译、链接过程中进行**优化处理**，生成的可执行程序效率更高。如果使用了优化选项，编译的时间将更长，目标程序不可调试，有效果但不能显著提升程序的性能。
    - `-O0` 不做任何优化，这是默认的编译选项
    - `-O` 或 `-O1` ：对程序做部分编译优化，对于大函数，优化编译占用稍微多的时间和相当大的内存，采用本项优化，编译器会尝试减少生成代码的尺寸、缩短执行时间，但并不执行需要占用大量编译时间的优化。
    - `-O2` ：这是**推荐的优化等级**，与 `O1` 相比 ，`O2` 优化在增加编译时间的基础上，提高了生成代码的执行效率。
	- `-O3` ：**最高最危险的优化等级**。用这个选项会延长编译代码的时间，并在使用gcc4.x的系统里不应全局启用。自从3.x的版本以来gcc的行为已经有了极大变化。在3.x，`-O3` 生成的代码也只是比 `-O2` 快一点而已，而gcc4.x中还未必更快。用 `-O3` 来编译所有的软件包将产生更大体积更耗内存的二进制文件，大大增加编译失败的机会或不可预知的程序行为（包括错误），这样做将得不偿失，过犹不及，在gcc4.x中使用 `-O3` 是不推荐的。
- `-c` 只编译、不链接成为可执行文件，通常用于把源文件编译成静态库或动态库 `.so` 。
- `-std=c++11` 使用此选项以支持C++11标准。
- `-I` 指定头文件所在的路径，这样在源代码文件中引用头文件时就不用加上路径。
- `-L` 指定静态/动态库文件所在的路径，和 `-l` 相互配合使用
- `-l` 指定静态/动态库的库名

# 3. 静态库和动态库
在实际开发中，我们把通用的函数和类分文件编写，称为**库**。在其他的程序中，可以使用库中的函数和类。

一般来说，通用的函数和类不提供源代码文件（安全性、商业机密），而是编译成二进制文件。库的**二进制文件**有两种：静态库和动态库。
## 3.1 静态库
**静态库的概念**
程序在编译时会把库的二进制代码，链接到目标程序中，这种方式称为**静态链接**。如果多个程序中用到了同一静态库中的函数或类，就会存在多份拷贝。

总的来说，用静态库编译和用源代码编译的效果是一样的，只是对于静态库来说，程序员看不到源代码。

**静态库的特点**：
1. 静态库的链接是在编译时期完成的，执行时代码加载速度快。
2. 目标程序的可执行文件比较大，浪费空间。
3. 程序的更新和发布不方便，如果某一个静态库更新了，所有使用它的程序都需要重新编译。

**制作静态库**
`g++ -c -o lib库名.a 源代码文件清单`

**使用静态库**
不规范的做法：`g++ 选项 源代码文件名清单 lib库名.a` 把静态库和源代码文件一起编译
规范的做法：`g++ 选项 源代码文件名情况 -L静态库文件所在的目录名 -l库名`

## 3.2 动态库
**动态库的概念**
程序在编译时不会把库文件的二进制代码链接到目标程序中，而是在运行时才载入。如果多个程序用到了同一动态库中的函数，那么在内存中只有一份，避免了空间浪费问题。

**动态库的特点**
1. 程序在运行的过程中，需要用到动态库时才把动态库的二进制代码载入内存。
2. 可以实现进程之间的代码共享，因此动态库也称为共享库。
3. 程序升级比较简单，不需要重新编译程序，只需要更新动态库就行了。
4. 如果动态库和静态库同时存在，编译器将优先使用动态库。

**制作动态库**
`g++ -fPIC -shared -o lib库名.so 源代码文件清单`

**使用动态库**
不规范的做法：`g++ 选项 源代码文件名清单 动态库文件名` 这种方法把动态库和源代码文件一起编译，把动态库当做静态库使用，不推荐
规范的做法：`g++ 选项 源代码文件名清单 -L库文件所在的目录名 -l库名` 

注意，使用动态库后，运行可执行程序时，需要提前设置 `LD_LIBRARY_PATH` 环境变量，在系统提供的动态库目录路径后面，用 `:` 分隔并添加指定动态库文件的目录。
# 4. makefile
在实际开发中，项目的源代码文件比较多，按类型、功能、模块分别存放在不同的目录和文件中，哪些文件需要先编译、哪些后编译，哪些文件需要重新编译，还有更多更复杂的操作。

`make` 是一个强大的使用工具，用于管理项目的编译和链接。`make` 需要一个编译规则文件 `makefile` ，可实现自动化编译。
```makefile
# 指定编译的目标文件是 libpublic.a 和 libpublic.so，多行书写时用/换行
all: libpublic.a libpublic.so 

# 编译 libpublic.a 需要依赖 public.h 和 public.cpp
# 采用增量编译，依赖的文件内容发生了变化，才重新编译 libpublic.a
libpublic.a: public.h public.cpp     # 目标: 依赖的文件清单
	g++ -c -o libpublic.a public.cpp # 这一行是编译指令

libpublic.so: public.h public.cpp
	g++ -fPIC -shared -o libpublic.so public.cpp

# clean用于清理编译目标文件，仅在make clean时才会执行
clean:
	rm -f libpublic.a libpublic.so

# 定义变量并在编译指令中通过 $() 使用变量
INCLUDEDIR=-I/home/zp/tools -I/home/zp/api
LIBDIR=-L/home/zp/tools -L/home/zp/api

demo01: demo01.cpp
	g++ -o demo01 demo01.cpp $(INCLUDEDIR) $(LIBDIR) -lpublic -lmyapi
```
# 5. `main` 函数的参数
`main` 函数有三个参数，`argc, argv, envp` ，标准写法如下：
```cpp
int main(int argc, char *argv[], char *envp[]) {
	return 0;
}
```
- `argc` 存放了程序参数的个数，包括程序名本身；
- `argv` 字符串的数组，存放了每个参数的值，包括程序名本身；
- `envp` 字符串的数组，存放了环境变量，数组的最后一个元素是 `NULL` 。

```cpp
int setenv(const char *name, const char *value, int overwrite);
// name 环境变量名
// value 环境变量值
// overwrite 0-如果环境变量不存在则增加，如果已存在则不替换其值；非0-如果不存在则增加，存在则替换
// 返回值 0-成功；-1表示失败（失败的情况极少见）
```
注意，此函数设置的环境变量只对本进程有效，不会影响Shell的环境变量。如果在运行程序时执行了 `setenv` 函数，进程终止后再次运行该程序，上次的设置是无效的。

# 7. GDB常用命令
如果希望程序可调试，编译时需要加 `-g` 选项，并且不能使用 `-O` 的优化选项。

| 参数         | 缩写  | 含义                                                                                                                 |
| :--------- | :-- | :----------------------------------------------------------------------------------------------------------------- |
| `set args` |     | 设置程序运行的参数。例如程序运行时需要 `./demo z1 z2 z3`，则设置参数的方法是 `set args z1 z2 z3`                                                |
| `break`    | `b` | 设置断点，`b Test.cpp:20` 表示在 `Test.cpp` 第20行设置断点，可以设置多个断点。                                                             |
| `run`      | `r` | 开始运行程序，程序运行到断点的位置会停下来，如果没有断点则一直运行下去。                                                                               |
| `next`     | `n` | 执行当前行语句，如果该语句为函数调用，不会进入函数内部。                                                                                       |
| `step`     | `s` | 执行当前行语句，如果该语句为函数调用，则进入函数内部。注意，如果函数是库函数或第三方提供的函数，用 `s` 也是进不去的，因为没有源代码，如果是自定义的函数，只要有源码就可以进去。                         |
| `print`    | `p` | 显示变量或表达式的值，如果 `p` 后面是表达式，则会执行这个表达式。**可以用来设置变量的值**。                                                                 |
| `continue` | `c` | 继续运行程序，遇到下一个断点停止，如果没有遇到断点，程序将一直运行。                                                                                 |
| `set var`  |     | 设置变量的值。假如程序中定义两个变量：`int i; char name[21];` ，`set var i = 10` 把 `i` 的值设置为10，`set var name="z3"` 把 `name` 设置为 `z3` 。 |
| `quit`     | `q` | 退出GDB                                                                                                              |

# 8. Linux的时间操作
C++11提供了操作时间的 `chrono` 库，从语言级别提供了时间操作的支持。`chrono` 库屏蔽了时间操作的很多细节，简化了时间操作。如果对Linux原生的时间操作不熟悉，很难用好 `chrono` 库。
## 8.1 `time_t` 别名
UNIX操作系统根据计算机产生的年代，把1970年1月1日作为UNIX的纪元时间，将从1970年1月1日起经过的秒数用一个整数存放。

`time_t` 用于表示时间类型，它是一个 `long` 类型的别名，在 `<time.h>` 文件中定义，表示从1970年1月1日0时0分0秒到现在的秒数。
`typedef long time_t;`
## 8.2 `time()` 库函数
`time()` 库函数用于获取操作系统的当前时间。

包含头文件：`<time.h>`
声明：`time_t time(time_t *tloc);`
有两种调用方法：
```cpp
time_t now = time(0); // 将空地址传递给time()，并将time()返回值赋给now
time_t now; time(&now); // 将变量now的地址作为参数传递给time()函数
```
## 8.3 `tm` 结构体
`time_t` 是一个长整数，不符合人类的使用习惯，需要转换为 `tm` 结构体，`tm` 结构体在 `<time.h>` 中声明，如下：
```cpp
struct tm
{
	int tm_year; // 年份，其值等于实际年份减去1900
	int tm_mon;  // 月份，取值区间为[0,11]，0代表一月，11代表12月
	int tm_mday; // 日期，一个月中的日期，取值区间为[1,31]
	int tm_hour; // 时，取值区间为[0,23]
	int tm_min;  // 分，取值区间为[0,59]
	int tm_sec;  // 秒，取值区间为[0,59]
	int tm_wday; // 星期，取值区间为[0,6]，0代表星期天，6代表星期六
	int tm_yday; // 从每年的1月1日开始算起的天数，取值区间为[0,365]
	int tm_isdst; // 夏令时标识符
}
```
## 8.4 `localtime()` 库函数
`localtime()` 函数用于把 `time_t` 表示的时间转换为 `tm` 结构体表示的时间。`localtime()` 不是线程安全的，`localtime_r()` 是线程安全的。

包含头文件：`<time.h>`
函数声明：
```cpp
struct tm *localtime(const time_t *timep);
struct tm *localtime_r(const time_t *timep, struct tm *result);
```
代码示例：
```cpp
#include <iostream>
#include <time.h> 
using namespace std;

int main() {
	time_t now = time(0); // 获取当前时间，存放在now中
	cout << "now=" << now << endl; // 显示当前时间，1970年1月1日到现在的秒数
	tm tmnow;
	localtime_r(&now, &tmnow); // 把整数的时间转换为tm结构体
	// 根据tm结构体拼接为习惯的字符串格式
	string stime = to_string(tmnow.tm_year + 1900) + "-"
		+ to_string(tmnow.tm_mon + 1) + "-"
		+ to_string(tmnow.tm_mday) + " "
		+ to_string(tmnow.tm_hour) + ":"
		+ to_string(tmnow.tm_min) + ":"
		+ to_string(tmnow.tm_sec);
	cout << stime << endl;
	return 0;
}
```
## 8.5 `mktime()` 库函数
`mktime()` 的功能与 `localtime()` 相反，用于把 `tm` 结构体时间转换为 `time_t` 时间。

包含头文件：`<time.h>`
函数声明：
```cpp
time_t mktime(struct tm *tm);
```
该函数主要用于时间的运算，例如把2022-10-01 15:30:25加30分钟。

思路：
1. 解析字符串格式的时间，转换为 `tm` 结构体；
2. 用 `mktime()` 把 `tm` 结构体转换成 `time_t` 时间；
3. 把 `time_t` 时间加 `30*60` 秒；
4. 把 `time_t` 时间转换为 `tm` 结构体；
5. 把 `tm` 结构体转换成字符串。

## 8.6 `gettimeofday` 库函数
用于获取1970年1月1日到现在的秒、和当前秒中已经逝去的微妙数，可用于程序的计时。

包含头文件：`<sys/time.h>`
函数声明：
```cpp
int gettimeofday(struct timeval *tv, struct timezone *tz);

struct timeval {
	time_t     tv_sec;  /* seconds */
	suseconds_t tv_usec; /* microseconds */
};

struct timezone {
	int tz_minuteswest; /* minutes west of Greenwich */
	int tz_dsttime; /* type of DST correction */
};
```
## 8.7 程序睡眠
如果需要把程序挂起一段时间，可以使用 `sleep()` 和 `usleep()` 两个库函数。

包含头文件：`<unistd.h>`
函数声明：
```cpp
unsigned int sleep(unsigned int seconds);
int usleep(useconds_t usec);
```
